# 水中描画の追加改善：共通コースティクスと接地陰影

今回の目的は、床・岩・キャラクターに別々の光が見える状態を減らし、同じ海の中に存在するように見せること。GameScene、入力、起動シーケンス、ImGuiのドッキング設定は変更していない。既存の環境パネルへ調整項目だけを追加した。

## 今回実装したこと

- **共通のコースティクス投影**：DepthFog処理内で可視面のワールド座標と法線を復元し、床・岩・草・通常の深度を書き込む不透明モデルへ同じアトラスを投影する。モデルごとのクラス編集は不要。
- **太陽方向と屈折**：空気から水への屈折率1.333を使い、受光点から平均水面への投影位置を求める。下向きの面や太陽が沈んだ状態への加算を抑える。ボリューム光の進行方向も同じ屈折方向へ修正。
- **材質と水深へのなじみ**：材質色に応じて光量を調整し、既存の水深照明・RGB吸収より前に適用する。暗い岩を一律の白い線で塗りつぶさない。
- **接地陰影**：周囲の深度を8方向、2段階の距離で参照し、岩の根元や隙間を控えめに暗くする。既定の半径1.8、強度0.30。背景、水面、半径外の物体は遮蔽対象から除外。
- **境界対策**：法線は深度が連続する側から復元。画面端を越えたAOサンプルは使用しない。遠方では効果をフェードし、コースティクスのアトラス境界には半テクセルの余白を設ける。
- **水面の除外**：波の最大変位を覆う高さの範囲を受光面から外す。水面の反射像へ床用の模様を重ねない。副作用として水面直下の薄い帯にある物体も効果が弱くなる。
- **従来方式との切替**：共通投影が有効なときは床・岩の局所コースティクスを止める。共通投影、世界座標の水中光学、DepthFog、Underwater Mediumのいずれかを切った場合は、床・岩の従来方式に戻る。Caustics Enableで両方を止められる。

追加項目は既存環境パネルの `Project Caustics on Scene`、`Underwater Contact Shading`、`Contact Strength`、`Contact Radius`。プリセット、強度、スケール、アニメーション時間は従来のCaustics設定を共有する。シーン終了時は新しいパラメータとテクスチャ参照も解除する。

## 実装範囲と制約

受光処理は `resources/shaders/OceanReceiverLighting.hlsli` に分離。環境設定は `UnderwaterEnvironment`、GPU定数とアトラスの受渡しは `RenderManager` に置いた。DepthFogの定数は256から320バイト、確保サイズは既存の256バイト切上げ式により512バイト。海底装飾の定数は240から256バイト。CPU側でサイズと主要オフセットをstatic_assertしている。

追加のレンダーターゲットや全画面描画パスはない。受光面では法線復元用に4回、接地陰影用に最大8回の深度参照、コースティクス用に2回のアトラス参照が増える。GPU時間の定量測定は未実施であり、無償の処理ではない。低性能環境ではまずContact Shadingをオフにする。

この実装は光子追跡やシャドウマップではない。平均水面からの投影であり、実際のGerstner波の曲率から集光を計算していない。岩の上側が覆われているか、画面外の物体が日光を遮るかは判定できない。水中の光柱には従来の低周波模様を残し、コースティクスのアトラスとの厳密な一致は行わない。

接地陰影は画面内の深度だけに基づく近似で、GTAOや多重散乱GIではない。法線マップの細部、透明物、深度を書かないエフェクト、後段で合成される専用レイヤーは対象外。AOは分離した環境光バッファではなくシーン色へ控えめに乗算している。

## 次の実装のおすすめ

1. **岩陰と光柱の遮蔽**：太陽用の深度シャドウマップを導入し、床・岩・コースティクス・光柱で共有する。洞窟や大きな岩を置いたときに光が突き抜ける問題を解決し、明るい浅瀬と暗い奥の差を作れる。まず単一領域から始め、必要になってからカスケード化する。
2. **水面に実在する物を映す**：水描画前のシーン色と深度を別リソースへ保存し、SSRと深度を使う屈折を追加する。画面外・失敗時は現在の空／海底近似へ滑らかに戻す。現在の海底反射は平面の近似なので、この変更で魚や岩が映るようになる。
3. **HDRとトーンマッピング**：現状のLDR中間バッファをHDRへ移し、ブルーム・露出をまとめて調整する。太陽や発光生物だけを明るくしながら砂・岩の模様を保持する基盤になる。全エフェクトのフォーマットと合成順の検証が必要。
4. **地形の大きな形**：平坦な床に丘・段差・岩のまとまりを作り、近景・中景・遠景に役割を持たせる。床高に依存する装飾・水面反射・ゲーム当たり判定の扱いを揃える必要があるため、チームで地形データの責務を決めてから進める。

この順は現行コードと画面からの提案であり、他作品が同じ順で開発されたという主張ではない。

## 検証

- Development / Release、x64の通常ビルド成功。既存の検証用ビルドスクリプトによる共有中間ディレクトリ警告MSB8028は残る。
- DepthFog PS、SeabedDetail PS/VSをDXC、Shader Model 6.0、`-Zpr -WX`でコンパイル成功。
- 固定カメラの環境専用QAビルドで、接地陰影のオン・オフと水面除外を比較。これはキャラクターやUIを除いた検証画像であり、通常ゲームの比較動画ではない。
- 水面を見上げる固定視点では、受光処理オン／オフのゲーム画像が同一であることを画素比較で確認（ウィンドウ枠・カーソル領域を除外）。海底視点ではコースティクスと接地陰影それぞれの変更を確認した。
- 通常Release実行ファイルも起動し、追加の開始操作なしにキャラクター、HUD、海底が描画されることを確認。検証のため起動したプロセスは終了済み。
- GameScene、入力処理、ドッキング設定の差分なし。新規操作をしなくても追加の描画が有効。

検証用実行ファイル・画像・固定カメラの設定はGit対象外の `generated/ocean-review/` に配置。通常プロジェクトから検証用Sceneを参照しない。
