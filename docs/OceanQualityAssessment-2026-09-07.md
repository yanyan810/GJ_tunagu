# 海洋ゲームとの画面品質比較と実装優先順位

## 結論

現状は水中らしい色・距離感・光の模様を備えた試作で、参考動画のSubnautica 2と並ぶ景観の完成度にはまだ届いていない。色の方向性は近づいたが、地形の大きな形、素材、植生の構成、光を遮る物体の関係に大きな差がある。

評価対象は、ユーザー提供の約74秒のSubnautica 2動画と、最新変更を含むツナ具の `clear-water-seabed.png` / `clear-water-midrange.png` / `clear-water-surface-oblique.png`。通常ゲームの確認画面も参照したが、環境専用画像から除かれているキャラクターやUIの品質を環境の採点に混ぜない。魚群などの動きの完成度、長時間のちらつき、GPU性能はこの比較から数値評価しない。

参考動画の見た目を10と置いた主観的な目安：

| 対象 | 現状の目安 | 判断理由 |
| --- | --- | --- |
| 水の色・透明感 | 4〜5 | 近くの暖色と青い遠景は成立。場所による濁り・明暗・色の変化はまだ少ない |
| コースティクス | 4〜5 | 動く光と虹色の縁は見える。一面で同じ性格の模様が目立ち、遮蔽との整合も不足 |
| 下から見た水面 | 3〜4 | スネルの窓と細波はある。実際の魚・岩が反射せず、模様の天井として見える部分がある |
| 地形・素材・植生 | 1〜2 | 広い平面、似た岩、疎らな草が主で、景色としての主役や奥行きの構成が乏しい |
| ライティング | 2〜3 | 接地陰影と水深減衰はあるが、日光が岩に遮られる影がない。明るい砂と岩陰の対比が弱い |
| 環境画面全体 | 2〜3 | 技術要素が景色を支える段階から、景色全体を完成させる工程へ進む必要がある |

点数は客観的ベンチマークや進捗率ではない。総合は項目の単純平均ではなく、画面を並べたときの視覚的な説得力の評価。画角・水深・地形・露出も異なるため、同条件のレンダラー比較でもない。

## 画面で目立つ差

1. **広い平面が主役になっている。** 参考映像では手前の砂、中景の岩・植生、奥の地形が重なり、移動すると景色が変わる。現在の平面とタイル装飾では、細部を増やしても大きな輪郭は変わらない。
2. **砂の情報をコースティクスが担いすぎている。** 規則的な砂の縞は弱まったが、光の模様を消したときに砂・石・堆積物として読める特徴が足りない。光を強める追加調整の優先度は低い。
3. **岩と植生の素材・形の差が大きい。** 参考映像には岩の割れ目、層、丸み、大きさの異なる植物の集まりがある。現在の岩の形と草の細い板状シルエットは単純で、近距離ほど差が出る。
4. **光の遮蔽がつながっていない。** 近傍の接地陰影だけでは、岩の反対側や洞窟で日光を遮る効果を作れない。
5. **水面の反射に具体的な景色がない。** 波の細かさだけでなく、周囲の物体が映って動くことが、水面をその場所に存在するものとして見せる。

## 推奨する実装順

### 1. 見せ場になる浅瀬を一区域完成させる

砂の起伏、特徴の違う少数の岩、密な植生と空いた砂地、奥に見えるアーチなどを配置する。広い全域に小物を均等に増やす構成は避け、泳ぐと景色が開ける短い経路を作る。素材には少なくとも色と法線・粗さの差を持たせ、岩の大きな割れ目や葉の輪郭は形状で支える。

提案上の `SeabedTerrainRenderer` / `ReefComposition` を `UnderwaterEnvironment` に所有させる構成なら、既存の環境描画呼出しを使える。新しいクラス名は設計候補で、まだ実装されていない。進行経路に起伏を入れる場合は当たり判定・装飾の床高を同じ地形データへ揃える必要がある。

FOV比較もこの区域で行う。現行は `Camera.cpp` の縦0.45rad（約25.8度）、横約44度で、Engine/GameにSetFovYの呼出しはない。まず縦45 / 55 / 65度などを比較候補にし、追従距離と画面上の敵の大きさを一緒に調整する。広角にすると未制作の空間も見えるので、地形の構成とセットで判断する。共有Cameraの初期値を一括変更する案は採らない。

### 2. 静的な環境から太陽の影を入れる

まず近景の1枚のシャドウマップとPCFで、砂・岩の影を作る。同じ遮蔽をコースティクスへ反映し、岩陰では光の模様も弱める。その後、光柱へ共有する。

環境所有の影描画クラスで静的地形を扱えば、GameSceneの変更を抑えられる。魚やスキニングモデルも影を落とす対象にする段階では、モデル側の描画登録・深度用パスが別途必要。影の範囲、bias、カメラ移動時の安定化も実装に含める。

### 3. HDRと露出を統一する

現行のシーン／中間ターゲットはR8G8B8A8_UNORM_SRGB。水面には局所的なハイライト圧縮があるが、全シーンのHDR照明と最終トーンマッピングはない。

シーン色をR16G16B16A16_FLOATへ移し、光とブルームを保持してから最終表示へ変換する。RenderManager、OffscreenPass、各3D PSOの形式を合わせ、UIは表示用の色空間で合成する。形式変更だけで完了とはせず、既存エフェクトの明るさを再検証する。

### 4. 水面に実際の物体を映す

水面が深度を書き込む前に、不透明シーンの色・深度を保存する。現行の呼出し順ではUnderwaterEnvironmentのDrawWaterDepth冒頭が候補。その入力を使って屈折と限定的なSSRを追加する。

水中からの反射対象は画面外になりやすく、SSRだけでは欠ける。既存の近似、環境プローブ、または限定的な平面反射を併用し、失敗時に滑らかに切り替える。水面の揺れ、岸・岩の境界、色の吸収を二重適用しないことも検証対象。

### 並行して行うこと

- **輪郭と動画の確認**：FXAAなどを小さく試し、草・岩のギザつきとぼけを比較。現行には素材内の細部フィルタはあるが、通常のFXAA/TAA/MSAA経路は見つからない。TAAには履歴、速度、ジッタ、透明物の扱いが必要。
- **GPU計測**：各パスの時間を測り、影・水・ポスト処理の予算を決める。現在の見た目の採点からフレームレートは推定しない。
- **魚群や水草の動き**：一区域がまとまったら、画面の広がりを示す群れと、流れを共有する植生を配置。通常ゲームの魚や障害物の役割とは別に責務を決める。

## 最初の到達目標

「Subnautica 2全体と並ぶ」を一度に狙うのではなく、海底へ近づく→岩陰を通る→景色が開ける→水面を見上げる、という30〜60秒の一経路を完成させる。

- コースティクスを切っても砂・岩・植生が見分けられる。
- モノクロでも前景・中景・遠景が読める。
- 岩陰では砂もコースティクスも暗くなる。
- 泳いだとき、地形と植物の配置で画面の構成が変わる。
- 同じ経路・画角・解像度で変更前後の動画を比較し、ちらつきとフレーム時間も確認する。

今回の作業は評価と設計提案。既存の未コミット描画変更を保持し、新しい描画機能の実装やゲーム操作の変更は行っていない。
