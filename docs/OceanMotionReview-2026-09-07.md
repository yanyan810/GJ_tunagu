# 改良後の海を、複数作品の公開資料と比較する

この文書は、今回の「改良後動画.mp4」を使った再確認の調査・実装メモです。公開資料、前回の検証画像、今回の動画から抽出した代表フレームを区別して評価します。後半には、今回の修正内容と確認できた動作検証結果を記録します。

## 現在の位置づけ

水中吸収、コースティクス、スネルの窓、影、HDR、画面内の実景反射・屈折という要素は揃いました。ただし、機能の名前が揃うことと、市販作品と同じ見た目になることは別です。現状は「海中の景色が成立した試作」であり、Subnautica 2、Sea of Thieves、ABZÛと並ぶ映像の完成度にはまだ届いていません。

前回の [浅瀬の検証画像](../generated/ocean-review/reef-showcase.png) と、提供された [Subnautica 2動画の代表フレーム](../generated/ocean-review/reference-subnautica-contact.png) を比較すると、手前の砂・中景の岩・奥のアーチという大きな構成は改善しています。一方、現在の植生は細く暗い輪郭が中心で、参考映像にある厚みのある黄橙色の群生とは印象が異なります。岩の割れ目や堆積物、場所による照明の変化も少なく、砂と岩の表情をコースティクスが担う割合がまだ大きいです。

この**環境専用の静止画**に限れば、提供されたSubnautica 2映像を10とした主観評価は全体で **3〜4程度**です。これは開発進捗、技術的な正しさ、性能の割合ではありません。制作区域、画角、水深、露出が異なり、同一条件のレンダラー比較でもありません。キャラクター、UI、音、入力応答、動画での安定性はこの点数に含めていません。

前回の「平面中心」の2〜3という評価から、一区域の形は増えました。しかし、作品全体の素材・形・動き・操作感を整える工程はこれからです。追加の効果で点数を上げようとするより、移動したときに違和感が出る箇所を減らす方を優先します。

## いま近い部分と、同等とは言えない部分

| 観点 | すでにあるもの | 残る差 |
| --- | --- | --- |
| 光の計算の土台 | RGB吸収、経路長による減衰、HDRの内部合成 | 場所ごとの照明・水質、照明成分の分離、反射像との一致 |
| 水面の現象 | 波と法線、フレネル、スネルの窓、画面内の反射・屈折 | 画面外や隠れた面、探索の切り替わり、接触泡、見上げたときの時間的な安定性 |
| 景観 | 起伏、静的な岩陰、アーチ、群生 | 近距離の岩・砂・葉の素材、植生の厚みと密度、一区域を超えた変化 |
| 水中の動き | 波、揺れる葉、粒子、既存の生物 | 生物と水草の反応、同じ流れを感じる動き、カメラや衝突と景観の整合 |

水面の反射・屈折は、現在の画面に存在する色と深度を使います。画面外の物体や隠れている面を取り戻せず、近似に切り替わる制限があります。加えて、今回の調査開始時点では、共通のpost方式の影・コースティクス・接地陰影が水面用コピーの後に適用されるため、それらは反射・屈折像に含まれません。[前回の実装メモ](OceanReefUpgrade-2026-09-07.md)も参照してください。

## 改善の優先順位

1. **動かしたときの破綻を減らす。** 水面の細線や反射が明滅する場合は、波の細部を画素の大きさに合わせて落とし、反射の命中／失敗を急に切り替えない。カメラが岩や地形の中へ入る、近い物体が急に隠れる、といった問題も見た目の優先課題に含める。原因を確認してから修正し、TAA追加だけで解決すると決めつけない。
2. **物体と水の境界を作る。** 船体や岸との接触、泡、浅い部分の透過色、濡れた面を、同じ水位と波に合わせる。Sea of Thievesのような全面的な波頭泡の前に、見せ場になる一か所へ絞る。
3. **直接見た照明と水面内の像を合わせる。** 反射・屈折の元画像にも受光処理を含める構成を検討する。必要な追加パスとコストを測り、どの画角で差が目立つかで採否を決める。
4. **素材と動きの方向性をそろえる。** 岩は少数でも形・割れ目・粗さを明確に分ける。草は細い線を一様に並べず、厚みのある輪郭と色のまとまりを作る。魚群は密度を増やすだけでなく、進路や見せたい物体へ視線を誘導する役割を持たせる。

FFTの波、岸の砕波、TAA、動的シャドウにはそれぞれ意味があります。ただし、現在の一区域に対してどこが不足しているかを確認して選びます。今回の目標である「見た人が驚く」印象には、効果の数よりも、近づく・横切る・見上げるという動作の間も景色が破綻しないことが必要です。

## 比較の進め方

静止画では色、形、素材、前景と遠景の重なりを確認します。動画では、波の動き、反射の切り替わり、草のちらつき、岩を通過するときのカメラを別に確認します。圧縮された動画のノイズだけからGPUの描画不具合を断定せず、固定カメラで時間だけを進める検証と、時間を止めてカメラだけ動かす検証で切り分けます。

GPU性能はFPSを映像から推定せず、同じ解像度・同じ経路で各パスの時間を測ります。今回はまだGPUミリ秒の比較結果がないため、画質評価から性能が同等、または改善したとは判断していません。

## 今回実装した変更

今回の修正は、水面の見上げ、地形へ接近する移動、明るい水面内のボスという、提供動画で気になった場面を対象にしました。前述の3〜4という評価は修正前の環境専用画像に対する評価です。以下の固定視点の確認だけを使って、市販作品との点差が縮まったという再採点はしていません。

| 対象 | 変更内容 | 主な実装・接続先 |
| --- | --- | --- |
| 水面越しの空 | 水面用の空を連続した方向関数から描く青空・雲・太陽へ変更。共有キューブマップに含まれる面の継ぎ目を、水面用の空へ持ち込まないようにした | [WaterSurface.PS.hlsl](../resources/shaders/WaterSurface.PS.hlsl) |
| 細かな波とスネルの窓 | 法線のサンプリング範囲を広げ、画素より細かい波を弱める。大きな波に小さな法線の波を重ね、全反射へ移る境界を複数サンプルでならす | [WaterSurface.PS.hlsl](../resources/shaders/WaterSurface.PS.hlsl)、[WaterSurfaceRenderer](../Engine/Render/WaterSurfaceRenderer.cpp) |
| 画面内反射・屈折の探索 | 近い面の深度だけを集めて連続したUVで復元し、画素の中心へ丸めることによる位置の飛びを抑える。厚み・画面端・面の占有率から命中の重みを連続的に決める。最初の不透明な面で探索を止め、背後の隠れた物体へ誤って抜けないようにした | [WaterSceneOptics.hlsli](../resources/shaders/WaterSceneOptics.hlsli)、[WaterSurfaceRenderer](../Engine/Render/WaterSurfaceRenderer.cpp) |
| プレイヤーと地形 | 描画に使用する静的な三角形に対して球を連続的に移動させ、面・辺・頂点との衝突後は面に沿って移動する。岩とアーチを一枚の高さ制限に置き換えず、アーチの開口を残す | [ReefCollisionWorld](../Engine/Render/ReefCollisionWorld.cpp)、[ReefSceneRenderer](../Engine/Render/ReefSceneRenderer.cpp)、[SeabedDetailRenderer](../Engine/Render/SeabedDetailRenderer.cpp) |
| 追従カメラ | 注視点から希望するカメラ位置までの地形との接触を調べ、地形内部に入らない位置へ補正する | [UnderwaterEnvironment](../Game/environment/UnderwaterEnvironment.cpp)、[ReefCollisionWorld](../Engine/Render/ReefCollisionWorld.cpp) |
| ボスの識別補助 | ボスに暖色の輪郭を付け、元のHDR色・深度と一緒に水面へ渡す。輪郭も屈折に従って曲がる。部品の負スケールで描画面が逆転しないよう補正し、非等方スケールや距離による太さの差を減らすため描画ピクセル単位で押し出す | [BossReadability](../Game/boss/BossReadability.cpp)、[Object3d](../Engine/3D/Object3d.cpp)、[Object3dCommon](../Engine/3D/Object3dCommon.cpp)、[Outline VS](../resources/shaders/Object3dOutline.VS.hlsl)、[Outline PS](../resources/shaders/Object3dOutline.PS.hlsl)、[共有定義](../resources/shaders/Object3dOutline.hlsli) |

輪郭は `SetOutlinePixelWidth(2.6f)` による明示的な選択です。従来の正値 `SetOutlineThickness()` は、モデル空間での押し出しと従来の面カリングを維持しています。既存のエフェクト定数バッファは96 bytesを保ち、余白だった2要素を描画解像度の逆数に使っています。現在の輪郭幅は1280×720のscene描画を基準とするため、拡大表示後の画面ピクセル数とは異なります。

## チームで共有する変更範囲

地形の衝突計算は独立した `ReefCollisionWorld`、シーンとの橋渡しは `UnderwaterEnvironment`、ボスの演出設定は `BossReadability` に置きました。[GameScene.cpp](../Game/scene/Main/GameScene.cpp) の今回の接続変更は3行追加・1行削除で、プレイヤーの登録と追従カメラの補正が中心です。競合しやすいシーンへ計算本体は追加していません。

[Player.cpp](../Game/player/Player.cpp) は2行追加、[Player.h](../Game/player/Player.h) はコールバック用の4行追加です。移動補正は、モデルや付属品の位置を更新する前に適用します。[Enemy.cpp](../Game/enemy/Enemy.cpp) からはボスの輪郭設定と既存ImGuiへの項目表示を呼び出します。

起動時の操作、ゲーム開始手順、ImGuiのドッキング操作は変更していません。既存の「Underwater Environment」に環境・カメラの衝突切り替え、既存のボス設定に輪郭の有効化・幅・輝度・色の項目を追加しています。

ボスについて、確認画像では反転した部品の全面塗りや大きな面の欠落は見られませんでした。船体の赤色自体は輪郭なしでも空から分離しています。輪郭幅や輝度をさらに上げても船体外周の弱さは直らず、継ぎ目がより目立つため、今回は2.6 render px・輝度1.35を維持しています。逆向きに膨らませたメッシュで描く方式のため、開いた面、法線の継ぎ目、細い部品では、一定幅の完全な外周線にはなりません。
